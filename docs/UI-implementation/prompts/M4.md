## Goal
Let a human review and resolve approval-required actions — while making the **metadata-only**
limitation unmistakable. Resolving an approval records a decision; it does **not** execute the
action.

## Backend
- `GET /api/approvals` — `ApprovalInbox.list_pending`; include risk, age, source turn, capability,
  status.
- `GET /api/approvals/{id}` — detail with payload preview and a diff for file-mutation proposals.
- `POST /api/approvals/{id}/resolve` — `{approve: bool, reason: str}` →
  `ApprovalInbox.resolve(...)`; response echoes `executes_action: false`.
- Reuse existing schemas/serialization; reject unknown request fields.

## Frontend
- `ApprovalQueue`: list with badges (`Approval-required`, risk).
- Approval detail: metadata preview + diff; approve/deny **requires a reason**.
- Persistent banner on all approval surfaces: *"Approval resolution is metadata-only. Recording a
  decision does NOT execute the action."*

## Tests
- Approve → `approval_received` event, response `executes_action=false`.
- Deny → `approval_denied`.
- Tampered `action_payload_sha256` → rejected.
- Frontend: queue renders; resolve calls client with reason; metadata-only banner present
  (assert in test).

## Don't
Don't add an execution relay; don't let the UI imply the action ran; don't allow payload edits.

## Definition of done
Full validation gate green (Python + frontend). Commit + push.
