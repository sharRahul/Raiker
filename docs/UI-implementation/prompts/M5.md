# Prompt — M5: Security Settings (Runtime Mutations + Secret Settings)

You are implementing **Milestone 5**. Read `01_INFORMATION_ARCHITECTURE.md`, `02_SECURITY_UX.md`,
`03_API_CONTRACTS.md`. Branch `claude/raiker-governed-agent-ui-zsqqt6`.

## Goal
Provide the **single, gated** path to enable/disable runtime modes and capability gates, behind a
step-up auth window — using the **existing** control routes only. Render fail-closed/deferred caps
as un-enableable. Secret Settings is read-only.

## Frontend (no new authority — reuse existing control routes)
- `StepUpAuthDialog`: re-confirm the acting human principal; collect `reason`, Tier-2
  `confirmation_token`, and threat-model ack as required; only then allow mutation calls.
- `SecuritySettingsPanel` → **Runtime Mutations**:
  - Rows from `GET /api/capability-gates` + `GET /api/runtime-mode`.
  - Enable/disable controls **disabled** unless `can_current_principal_change=true`.
  - Calls existing `POST /api/runtime-mode/{activate,disable}` and
    `POST /api/capability-gates/{cap}/{set,disable}`.
  - Fail-closed/deferred caps (no executor / `disabled_deferred`) shown un-enableable with
    `DisabledCapabilityExplainer` (status, why, what's required, future/deferred vs gated).
- `SecuritySettingsPanel` → **Secret Settings**: read-only redaction/deny-policy view +
  prominent **"Secret storage is not implemented (deferred)"** notice. No secret input fields.
- Keep top-level Capabilities and Runtime Gates **read-only**.

## Backend
- No new mutation routes. If the control routes need a `confirmation_token`/`reason` pass-through
  that isn't already wired, extend the existing request schemas minimally and forward to
  `RuntimeControlService` / `RuntimeAuthority` (do not add logic in the route).

## Tests
- Enabling a **supported** gate succeeds and is event-logged.
- A fail-closed cap cannot be enabled (explainer shown); assert the control call is blocked.
- Non-authorised / AI principal → 403 + plain-English reason; controls hidden/disabled.
- No secret input exists anywhere (assert in frontend test).

## Don't
Don't enable unsupported runtimes; don't store secrets; don't add client-side gate logic; don't
create an admin shortcut or alternate mutation path.

## Definition of done
Full validation gate green (Python + frontend). Commit + push.
