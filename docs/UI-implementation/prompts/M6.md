# Prompt — M6: Diagnostics & Validation

You are implementing **Milestone 6**. Read `03_API_CONTRACTS.md`. Branch
`claude/raiker-governed-agent-ui-zsqqt6`.

## Goal
Give operators an honest readiness/diagnostics view. Surface local readiness, validator status,
missing configuration, disabled capabilities, and provider health — **without** claiming
production readiness beyond the local single-user runtime, and **without** running shell or
validators from the browser.

## Backend
- `GET /api/diagnostics` — reuse `RuntimeControlService.get_runtime_readiness` plus existing
  readiness reports. Return stored/derived status only (no shell execution). Schema:
  `{readiness:{...}, disabled_capabilities:[...], missing_config:[...], provider_health:[...]}`.

## Frontend
- `DiagnosticsPanel`: render readiness summary, validator/readiness results, missing config,
  disabled caps, provider health. Use the badge system; never colour-only.
- Show an explicit scope note: "Status reflects the local single-user runtime only."

## Tests
- Backend: diagnostics schema matches `/api/runtime-readiness`-derived data; auth required;
  no shell invocation path.
- Frontend: panel renders each section from fixtures; scope note present.

## Don't
Don't run validators/shell from the browser; don't overclaim readiness; don't fabricate provider
health.

## Definition of done
Full validation gate green (Python + frontend). Commit + push.
